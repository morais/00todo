# 00Todo promotional screenshots

Run `marketing/screenshots/capture-ios.sh` from the repository root to capture three app-only screens on both iPhone 17 Pro (1206×2622) and iPad Pro 13-inch M4 (2064×2752), then compose six promotional images. The source captures are in `artifacts/screenshots/raw/{iphone-6.3,ipad}/`; the headline/device-frame images are in `artifacts/screenshots/promotional/{iphone-6.3,ipad}/`. Generated images are ignored by Git, as in 00Widget. Re-run `marketing/screenshots/generate-promotional.py` to recompose without recapturing.

The frames are Available, Upcoming, and the Weekend shopping project. They use the same demo-data catalog as Settings → Screenshots. A screenshot-only build flag plus launch argument enables the local fixture; ordinary app and TestFlight builds cannot enter it. The capture does not sign in, call the API, or change account data. The script pins the simulator status bar to 9:41, runs UI tests, verifies all three PNGs and their device dimensions, and records SHA-256 checksums in `.capture-manifest.json`. The compositor verifies those checksums before generating frames and records source/output hashes in `.composition-manifest.json`. A failed partial run cannot be mistaken for a fresh complete set.

For one device class only, run `marketing/screenshots/capture-ios.sh iphone` or `marketing/screenshots/capture-ios.sh ipad`. The script needs Xcode 27, XcodeGen, iOS 27 simulators with the device names above, and Python 3 with Pillow. The first capture is an XCUITest run and may require the Simulator/DeviceHub window to be open. The promotional treatment follows 00Widget's off-white editorial header, short brand-color rule, and real simulator screen in device chrome, cropped at the bottom. No widgets, Home Screen, or mock task UI are included.
